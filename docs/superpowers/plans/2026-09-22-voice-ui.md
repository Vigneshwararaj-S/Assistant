**Goal:** A working Tauri desktop app with a voice-interactive, animated
lemon-mirchi charm character, talking to the existing local chat/tool-calling
system over a websocket.

**Architecture:** A new FastAPI backend (`src/webapp_backend/`) wraps the
existing `Chat`/backend/tool-client stack unchanged in behavior, adding one
small backward-compatible interface change (an output callback instead of
hardcoded `print`), plus a local voice pipeline (`faster-whisper` STT,
`kokoro` TTS). A new Tauri + React frontend (`frontend/`) renders the charm
character and handles mic capture / audio playback, talking to the backend
over one WebSocket connection.

**Tech Stack:** FastAPI, uvicorn, faster-whisper, kokoro, Tauri, React,
TypeScript. Builds on the existing `src/chat.py`, `src/backends/`,
`src/tool_client.py`, `src/mcp_server/` unchanged in external behavior.

**Spec:** `docs/superpowers/specs/2026-09-22-voice-ui-design.md`

## Global Constraints

- No cloud speech APIs — STT and TTS must both run fully locally
  (`faster-whisper`, `kokoro`), per the spec.
- The existing CLI (`src/main.py`) must keep working identically after this
  plan — the callback change in Task 1 must be backward-compatible.
- No automated test suite exists anywhere in this project — verification is
  manual throughout, consistent with all prior work here.
- Character animation states, exact visuals, and their SVG/CSS reference
  implementations are already fully specified in
  `.superpowers/brainstorm/803-1790108288/content/` (gitignored,
  session-local) — port from there, don't redesign.
- A real, confirmed bug pattern to avoid when porting the character
  animations: a CSS `animation` setting `transform` on an element with a
  static SVG `transform="..."` attribute silently replaces it instead of
  composing. Always split static position (outer element, plain attribute)
  from animation (inner element, CSS only, no attribute transform of its
  own) — hit this bug 3 times independently during brainstorming before it
  became reflexive; the reference mockups already have it fixed, but a
  naive port that flattens the DOM structure could reintroduce it.

```python
# src/webapp_backend/server.py
import asyncio
import sys
from pathlib import Path

from fastapi import FastAPI, WebSocket, WebSocketDisconnect

sys.path.insert(0, str(Path(__file__).resolve().parent.parent))
from chat import Chat
from tool_client import ToolClient
from backends.ollama_backend import OllamaBackend

MCP_SERVER_DIR = Path(__file__).resolve().parent.parent / "mcp_server"

app = FastAPI()


def build_chat() -> tuple[Chat, list[ToolClient]]:
    servers = [
        [str(MCP_SERVER_DIR / "tools_server.py")],
        [str(MCP_SERVER_DIR / "filesystem_server.py"), "."],
        [str(MCP_SERVER_DIR / "apps_server.py")],
        [str(MCP_SERVER_DIR / "web_server.py")],
    ]
    tool_clients = [ToolClient(command=sys.executable, args=a) for a in servers]
    backend = OllamaBackend("qwen2.5:3b", max_new_tokens=256, temperature=0.7)
    return Chat(backend, tool_clients), tool_clients


@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()
    loop = asyncio.get_event_loop()
    chat_app, tool_clients = await loop.run_in_executor(None, build_chat)

    try:
        while True:
            message = await websocket.receive_json()
            if message["type"] != "user_text":
                continue

            queue: asyncio.Queue = asyncio.Queue()

            def on_token(text: str, _loop=loop, _queue=queue):
                _loop.call_soon_threadsafe(_queue.put_nowait, text)

            def run_chat():
                chat_app.chat(message["content"], on_token=on_token)
                loop.call_soon_threadsafe(queue.put_nowait, None)

            future = loop.run_in_executor(None, run_chat)
            while True:
                token = await queue.get()
                if token is None:
                    break
                await websocket.send_json({"type": "token", "content": token})
            await future
            await websocket.send_json({"type": "turn_complete"})
    except WebSocketDisconnect:
        pass
    finally:
        for tc in tool_clients:
            tc.close()


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

Note on the design here: `chat_app.chat(...)` is a blocking, synchronous call
(it runs model generation on its own thread internally, per the existing
`_generate` implementation), so it's run via `loop.run_in_executor` to avoid
blocking the async event loop. `on_token` is called from that executor
thread, so it uses `call_soon_threadsafe` to safely hand tokens back to the
event loop's queue — the same kind of sync/async bridging pattern already
used in `ToolClient`.

# src/webapp_backend/voice.py
from faster_whisper import WhisperModel


class Transcriber:
    def __init__(self, model_size: str = "base"):
        # CPU + int8, deliberately -- the GPU is already busy running the
        # chat model; whisper's "base" size is small enough to run well on
        # CPU without meaningfully slowing down a turn.
        self.model = WhisperModel(model_size, device="cpu", compute_type="int8")

    def transcribe(self, audio_path: str) -> str:
        segments, _info = self.model.transcribe(audio_path, beam_size=5)
        return " ".join(segment.text.strip() for segment in segments)
```

import io

import soundfile as sf
from kokoro import KPipeline


class Speaker:
    def __init__(self, voice: str = "af_heart"):
        self.pipeline = KPipeline(lang_code="a")
        self.voice = voice

    def synthesize(self, text: str) -> bytes:
        buffer = io.BytesIO()
        for _graphemes, _phonemes, audio in self.pipeline(text, voice=self.voice):
            sf.write(buffer, audio, 24000, format="WAV")
        return buffer.getvalue()
```

- [ ] **Step 1: Add mic capture**

Replace the manual state-switcher buttons and test-message button with a
push-to-talk button using the browser `MediaRecorder` API:

```tsx
const [recorder, setRecorder] = useState<MediaRecorder | null>(null);

const startRecording = async () => {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const mr = new MediaRecorder(stream, { mimeType: "audio/webm" });
  const chunks: Blob[] = [];
  mr.ondataavailable = (e) => chunks.push(e.data);
  mr.onstop = async () => {
    const blob = new Blob(chunks, { type: "audio/webm" });
    const buffer = await blob.arrayBuffer();
    const base64 = btoa(String.fromCharCode(...new Uint8Array(buffer)));
    setCharmState("thinking");
    wsRef.current?.send(JSON.stringify({ type: "audio_chunk", data: base64 }));
  };
  mr.start();
  setRecorder(mr);
  setCharmState("listening");
};

const stopRecording = () => recorder?.stop();
```

Note: `MediaRecorder` captures `webm`/`opus` by default in most browsers, not
